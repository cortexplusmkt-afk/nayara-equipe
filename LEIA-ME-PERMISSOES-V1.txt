NAYARA GESTÃO — PERMISSÕES + USUÁRIOS V1

PRÉ-REQUISITO
Este pacote assume que o Auth V1 já está instalado e funcionando:
- login real
- cookie HttpOnly
- AuthGuard global
- UsersModule / AuthModule
- usuários ADMIN / OPERATOR / VIEWER

O QUE MUDA

BACKEND
1. DocumentsController
   ADMIN / OPERATOR somente.
   VIEWER não acessa upload, OCR, revisão, finalização ou metadados de documentos.

2. RegistrationsController
   Todos autenticados:
   - GET /registrations
   - dashboard
   - mapa
   - território
   - detalhe

   ADMIN / OPERATOR:
   - POST /registrations/geocode-pending
   - GET /registrations/:cadastroId/pdf
   - PUT /registrations/:cadastroId

3. RolesController
   - GET: todos autenticados
   - POST: ADMIN

4. ElectoralDataController
   - status e polling-place: todos autenticados
   - import-local: ADMIN

5. UsersController
   Já permanece ADMIN-only, conforme Auth V1.

6. AuthGuard
   Agora consulta o usuário atual a cada requisição.
   Se o administrador desativar um usuário, o próximo request desse usuário recebe 401.
   Alterações de perfil também passam a valer no backend imediatamente.

FRONTEND
- RequireRole.tsx
- rotas de criação/revisão/finalização: ADMIN / OPERATOR
- Documentos: ADMIN / OPERATOR
- Configurações: ADMIN
- Sidebar oculta Documentos para VIEWER e Configurações para não-admin
- Configurações ganha gestão de usuários
- criação de usuário
- alteração de perfil
- ativação/desativação
- redefinição de senha em campo password
- status da autenticação atualizado
